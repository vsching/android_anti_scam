## Issue E02-003: Link Check Flow (3-Layer Architecture)

### Tasks
1. File: `app/src/main/java/com/safeanot/app/core/util/UrlNormalizer.kt`
   Action: Create
   Details: Normalize URLs: lowercase, strip protocol/path/query/www. Handle Punycode. Extract root domain.

2. File: `app/src/main/java/com/safeanot/app/core/domain/model/LinkVerdict.kt`
   Action: Create
   Details: Domain model: `domain`, `verdict` (Enum: SAFE, SUSPICIOUS, DANGEROUS, UNKNOWN), `reason`, `confidence`.

3. File: `app/src/main/java/com/safeanot/app/core/domain/repository/LinkRepository.kt`
   Action: Create
   Details: Interface: `checkLink(input: String): Flow<LinkVerdict>`.

4. File: `app/src/main/java/com/safeanot/app/core/data/repository/LinkRepositoryImpl.kt`
   Action: Create
   Details: Implementation of 3-layer check: 1) Local DB hit → return. 2) Bloom filter negative → return UNKNOWN. 3) Bloom positive → call API `/api/check`. Cache API result in local DB.

5. File: `app/src/main/java/com/safeanot/app/core/domain/usecase/CheckLinkUseCase.kt`
   Action: Create
   Details: Orchestrate normalization and repository call.

### Tests
- `app/src/test/java/com/safeanot/app/core/util/UrlNormalizerTest.kt` -- test various URL formats, subdomains, and Punycode
- `app/src/test/java/com/safeanot/app/core/domain/usecase/CheckLinkUseCaseTest.kt` -- verify 3-layer priority (Local > Bloom > API)

### Acceptance Criteria
- Local DB hits resolve in <10ms
- Bloom filter correctly gates API calls (no API call if Bloom filter is negative)
- Punycode domains normalized correctly
- Results are cached locally after API fallback
