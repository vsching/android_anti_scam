## Issue E11-002: Admin CLI for Allowlist & Blocklist Management

### Tasks

1. **Create admin.sh CLI script**
   - File: `scripts/admin.sh`
   - Action: Create
   - Details: Bash script with usage help and subcommand dispatch: `allowlist-add`, `allowlist-remove`, `blocklist-add`, `blocklist-remove`, `list`. Set `WORKERS_DIR` to `backend/workers` for wrangler context.

2. **Implement domain validation**
   - File: `scripts/admin.sh`
   - Action: Create (continued)
   - Details: Validate domain format with regex matching the rules in `backend/pipeline/src/normalize.py`: must contain a dot, only valid hostname chars, no protocol prefix. Reject invalid domains with error message before any KV write.

3. **Implement allowlist-add subcommand**
   - File: `scripts/admin.sh`
   - Action: Create (continued)
   - Details: `allowlist-add <domain> <entity> <category>` runs `cd backend/workers && npx wrangler kv:key put --binding=VERDICTS "allowlist:<domain>" '<json>'` where JSON is `{"domain":"<domain>","verdict":"safe","category":"<category>","entity":"<entity>","reason":"Manually allowlisted","added_at":"<ISO timestamp>"}`.

4. **Implement blocklist-add subcommand**
   - File: `scripts/admin.sh`
   - Action: Create (continued)
   - Details: `blocklist-add <domain> <reason>` runs `cd backend/workers && npx wrangler kv:key put --binding=VERDICTS "<domain>" '<json>'` where JSON is `{"domain":"<domain>","verdict":"dangerous","reason":"<reason>","source":"manual_override","confidence":1.0,"added_at":"<ISO timestamp>"}`.

5. **Implement remove subcommands**
   - File: `scripts/admin.sh`
   - Action: Create (continued)
   - Details: `allowlist-remove <domain>` deletes `allowlist:<domain>` key; `blocklist-remove <domain>` deletes bare `<domain>` key. Both require interactive `y/N` confirmation before executing `npx wrangler kv:key delete --binding=VERDICTS`.

6. **Implement list subcommand**
   - File: `scripts/admin.sh`
   - Action: Create (continued)
   - Details: `list --allowlist` runs `npx wrangler kv:key list --binding=VERDICTS` and filters keys starting with `allowlist:`. `list --blocklist` filters keys that do NOT start with `allowlist:` and are not internal cache keys. Display domain, entity/reason from fetched values.

7. **Add admin CLI test**
   - File: `scripts/test-admin-cli.sh`
   - Action: Create
   - Details: Test script that creates a mock `wrangler` shim, exercises each subcommand, validates correct `wrangler kv:key` invocations, tests domain validation rejection, and tests confirmation prompt handling.

### Tests
- `scripts/test-admin-cli.sh` -- validates subcommand parsing, domain validation, wrangler command construction, confirmation on removals

8. **Add cache purge after admin writes**
   - File: `scripts/admin.sh`
   - Action: Create (continued)
   - Details: After each `allowlist-add`, `blocklist-add`, `allowlist-remove`, `blocklist-remove`, call `curl -X DELETE -H "X-Admin-Key: $ADMIN_SECRET" "https://safeanot-api.management-481.workers.dev/api/admin/cache/<domain>"` to invalidate the Cache API entry. The script must read `ADMIN_SECRET` from env var (required). This is required because `/api/check` caches verdicts for 1 hour — without purging, admin changes are delayed up to 3600s.

9. **Filter internal keys from list output**
   - File: `scripts/admin.sh`
   - Action: Create (continued)
   - Details: The VERDICTS KV namespace is mixed-use (contains `alerts:*`, `data:manifest:*`, cache entries). The `list` command MUST filter by prefix: `allowlist:` for allowlist entries, and exclude keys matching `allowlist:*`, `alerts:*`, `data:*`, `cache:*` for blocklist entries. Use `--prefix` flag with `wrangler kv key list`.

10. **Handle KV pagination in list**
    - File: `scripts/admin.sh`
    - Action: Create (continued)
    - Details: `wrangler kv key list` returns paginated results (max 1000 per page). Implement cursor-based pagination loop to fetch all entries when the allowlist/blocklist grows beyond 1000 keys.

### Acceptance Criteria

## Issue E11-003: Admin API Endpoints (Auth-Protected)

### Tasks

1. **Create admin auth middleware**
   - File: `backend/workers/src/middleware/admin-auth.ts`
   - Action: Create
   - Details: Export `validateAdminAuth(request, env)` that checks `X-Admin-Key` header against `env.ADMIN_SECRET` using timing-safe comparison (via `crypto.subtle.timingSafeEqual`). Returns 401 Response on failure, null on success. Use Cloudflare's built-in `ratelimit` binding for rate limiting (10 req/min) instead of non-atomic KV counters — add a new `[[unsafe.bindings]]` entry in wrangler.toml for `RATE_LIMITER_ADMIN`.

## Implementation Order

Recommended sequence (respects internal dependencies):

1. **E11-001** -- Establish the daily GitHub Actions runner first because every other operational safeguard depends on the pipeline executing automatically.
2. **E11-002** -- Add the admin CLI next because it is the fastest path to unblock manual allowlist/blocklist operations without waiting for API work.
3. **E11-004** -- Add smoke tests and `/api/health` before expanding admin surface area so pipeline failures and stale data are visible immediately.
4. **E11-003** -- Add auth-protected admin APIs after CLI and health checks exist, reusing the same KV conventions and adding D1 auditability.
5. **E11-005** -- Harden source resilience last because it builds on the automated run, health monitoring, and existing anti-poisoning pipeline behavior.
